# M3 — Reading analysis vertical slice

Goal:

```text
select passage -> Alt+Q -> translation + selected difficult words + useful expressions
```

This milestone turns the passage flow from "translate only" into the
product's core reading analysis. One provider round trip returns the
translation, a deliberately selective vocabulary list, and an exhaustive
list of useful expressions, all in the same resident window introduced in
M1. Word selections intentionally keep their M1 behavior until M4.

## Provider contract

The passage request now asks for a richer versioned JSON object (schema
version stays 1; the M2 translation-only object is a strict subset and the
M2 parser already ignored unknown keys):

```json
{
  "schema_version": 1,
  "translation": "……",
  "vocabulary": [
    {
      "surface": "acknowledged",
      "lemma": "acknowledge",
      "contextual_meaning": "响应、确认（中断）",
      "reason": "技术语境下的特殊含义"
    }
  ],
  "expressions": [
    {
      "surface": "not so much A as B",
      "kind": "sentence_pattern",
      "meaning": "与其说是 A，不如说是 B",
      "explanation": "不能逐字直读的句型"
    }
  ]
}
```

`kind` is one of `phrasal_verb`, `idiom`, `slang`, `collocation`,
`fixed_expression`, `contextual_meaning`, `sentence_pattern`,
`technical_usage`. `lemma`, `reason` and `explanation` are optional, and
whole sections may be omitted when there is nothing worth reporting.

Validation rules:

- the translation itself is validated strictly (schema version, non-empty,
  size caps) and its failure rejects the response;
- notes are converted leniently: an item with a missing required field, an
  unknown `kind`, or an empty surface is dropped instead of failing the
  whole analysis, and lists are truncated at runaway caps (16 vocabulary
  notes, 64 expression notes).

## Setup

Identical to M2 — the same `~/.config/seltrans/config.toml` and API-key
environment variable. No configuration changes are required to upgrade.

## Expected behavior

- Selecting a passage and pressing `Alt+Q` shows the original text
  immediately with an "Analyzing…" state; translation, vocabulary and
  expressions fill in together when the provider answers.
- The window's fixed area shows the original text and the translation.
  Below it, Vocabulary and Expressions are parallel tabs (`AdwViewStack`
  with a wide `AdwViewSwitcher`); each tab scrolls independently inside
  its own area, and tab badges show the item counts.
- A tab appears only when the provider reported items for it; when only
  one section has content it renders without the switcher, and when both
  are empty (simple sentence) the whole notes area is hidden.
- The Vocabulary tab stays small: the prompt demands genuinely difficult,
  uncommon, technically important or contextually surprising words, never
  a mechanical word list.
- The Expressions tab surfaces phrasal verbs, idioms, slang,
  collocations, fixed expressions, non-literal/context-specific meanings,
  sentence patterns (given in generalized form, e.g. `not so much A as B`)
  and technical usages whose conventional meaning differs from everyday
  usage — recall is preferred over aggressive filtering.
- Meanings, reasons and explanations are Simplified Chinese.
- Word mode is unchanged until M4.
- Stale-result fencing, error mapping and resident behavior are exactly
  the M1/M2 contract; only the rendered content is richer.

## Manual acceptance checklist

Requires the M1 setup (resident running, `Alt+Q` bound to
`seltrans-trigger`), plus a working OpenAI-compatible endpoint and key.

1. Select a technically dense sentence containing an idiom or pattern
   (for example "This is not so much a performance problem as a
   correctness problem.") and press `Alt+Q`: the window shows the
   translation, few if any vocabulary words, and the sentence pattern
   with its Chinese meaning.
2. Select a paragraph with several uncommon words: the Vocabulary list
   stays short and does not enumerate common words.
3. Trigger a passage while an older request is in flight: only the newer
   passage's analysis is displayed.
4. Stop the network or use a tiny `timeout_secs`: the window reports a
   timeout; translation/notes from the previous trigger are not left
   half-updated.
5. Repeat triggers reuse the same window; both tabs are rebuilt with fresh
   rows and their scroll positions reset for the new result.

## Troubleshooting

If text in the result window ever looks doubled or overlapped after many
reused requests: widget allocations have been verified correct for this
layout (multi-trigger, repopulated and scrolled states), and the app now
forces a full repaint each time a result is displayed. Should artifacts
still appear on Fedora with GTK 4.22+, try `GSK_RENDERER=cairo seltrans` —
if that removes them, the ghosting is a GL/ngl renderer texture-cache
issue rather than seltrans layout, and is worth reporting against gtk4.

## Automated coverage

Provider behavior is exercised against a local mock HTTP server
(`crates/seltrans-core/tests/openai_provider.rs`): request shape
(including the SELECTIVE/exhaustive prompt rules and the kind enum),
fenced/prose-wrapped JSON recovery, schema-version enforcement, per-item
degradation (dropped malformed vocabulary rows and unknown `kind`s),
runaway-list truncation, 401/429/500 mapping, timeout classification,
missing-key and unreachable-endpoint errors, plus payload unit tests in
`crates/seltrans-core/src/openai.rs`. The GTK-side rendering and fencing
reuse the M1/M2 arrival path and remain covered by desktop acceptance.

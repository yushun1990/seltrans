# M2 — Passage translation vertical slice

Goal:

```text
select passage -> Alt+Q -> Simplified Chinese translation in the resident window
```

This milestone adds the first network analysis on top of the M1 resident
flow. Word selections intentionally keep their M1 behavior until the
detailed lexical view lands in M4.

## Configure a provider

Create the configuration file (see [config.example.toml](config.example.toml)):

```text
~/.config/seltrans/config.toml
```

Minimal contents for any OpenAI-compatible endpoint:

```toml
[providers.openai-compatible]
base_url = "https://api.deepseek.com/v1"
model = "deepseek-chat"
```

Export the API key before starting the resident (the variable name is
configurable via `api_key_env`; default `SELTRANS_API_KEY`):

```bash
export SELTRANS_API_KEY=sk-...
./target/release/seltrans
```

The key is read from the environment at request time and is never stored in
the config file or written to disk by seltrans.

## Expected behavior

- Selecting a passage and pressing `Alt+Q` shows the original text
  immediately with a loading indicator; the translation fills in when the
  provider answers. The network call runs off the GTK thread.
- Only the newest invocation is ever displayed: if a newer trigger arrives
  while an older request is still in flight, the older result is discarded
  (the same sequence fencing M1 introduced for trigger bursts).
- Failures show a compact, actionable message in the window: missing
  configuration, missing API key, timeout, bad credentials (401/403), rate
  limiting (429), unreachable endpoint, or a malformed provider response.
- The provider is asked to return a versioned JSON object
  (`{"schema_version":1,"translation":"..."}`); the payload is validated
  (schema version, non-empty translation, size caps) before display, with
  lenient recovery of JSON wrapped in prose or code fences.
- A missing or invalid config does not break the resident M1 behavior; the
  reason appears in the window the first time a passage is translated, and
  on stderr at startup.
- Word-mode selections still show only the classifier label; the detailed
  lexical view is M4.

## Manual acceptance checklist

Requires the M1 setup (resident running, `Alt+Q` bound to
`seltrans-trigger`), plus a working OpenAI-compatible endpoint and key.

1. With a valid config and key, select an English sentence and press
   `Alt+Q`: the same M1 window shows the original, a loading state, then a
   natural Chinese translation.
2. Trigger a long passage, then immediately select and trigger a shorter
   one: only the shorter passage's translation is displayed.
3. Stop the network (or set `timeout_secs = 2` against a slow endpoint):
   the window reports a timeout instead of hanging.
4. Remove the API key from the environment and restart: the window reports
   which variable to export.
5. Point `base_url` at an unreachable host: the window reports a network
   error.
6. Rename the config file away and restart: the resident still starts and
   M1 behavior still works; translating a passage explains that
   translation is not configured.
7. Repeat triggers reuse the same window; no duplicate windows, no GTK
   re-initialization.

## Automated coverage

Provider behavior is exercised against a local mock HTTP server
(`crates/seltrans-core/tests/openai_provider.rs`): request shape and
authorization header, fenced/prose-wrapped JSON recovery, schema-version
enforcement, 401/429/500 mapping, timeout classification, missing-key and
unreachable-endpoint errors, plus config parsing unit tests. The GTK-side
fencing reuses the M1 arrival path and remains covered by desktop
acceptance.

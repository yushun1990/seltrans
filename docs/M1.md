# M1 — Try the selection-to-window vertical slice

This milestone **does not call an LLM**. It verifies the resident, warm-trigger
interaction before translation providers or learning persistence are added.

## Fedora / GNOME / Wayland prerequisites

```bash
sudo dnf install rust cargo gtk4-devel libadwaita-devel wl-clipboard pkgconf-pkg-config
cargo build --release
```

The build produces two executables: `seltrans` (the resident GTK
application; the only binary that links GTK) and `seltrans-trigger` (the
warm-path trigger; it links no GUI toolkit at all).

Start one resident instance **manually** from a terminal:

```bash
./target/release/seltrans
```

Do not run multiple resident instances. The initial result window remains
hidden until the first shortcut invocation. Keep the process running between
lookups; Ctrl+C in the terminal stops it.

In GNOME **Settings → Keyboard → View and Customize Shortcuts → Custom
Shortcuts**, add:

- Name: seltrans
- Command: /absolute/path/to/seltrans/target/release/seltrans-trigger
- Shortcut: Alt+Q (resolve any conflicting shortcut first)

Select English text in a Wayland application and press Alt+Q. The trigger
reads the current **primary** selection via wl-paste --primary --no-newline
**before** the resident window receives focus. The original text is displayed
with a deterministic word/passage label. Press Esc or use the window close
control to hide it; the next trigger should reuse that very same window.
Use **Quit** to end the resident process explicitly.

You can also test manually, after selecting some text:

```bash
./target/release/seltrans-trigger
```

## Expected behavior and current boundaries

- The resident owns exactly one GTK window and a private, bounded Unix socket
  under XDG_RUNTIME_DIR/seltrans/.
- The trigger is the dedicated `seltrans-trigger` executable built from the
  GUI-free core crate; it never initializes GTK and never links it.
- When the resident is unavailable, the trigger exits nonzero with a clear
  instruction to start it. wl-paste failures include wl-paste's own stderr
  diagnostic (for example: not a Wayland session, or no primary-selection
  support in the compositor).
- Empty/non-text primary selections, missing wl-paste, invalid UTF-8, and
  selections above 64 KiB are rejected explicitly.
- A resident acknowledges a request **only when it has entered the bounded
  request queue**, not just because a socket connection opened.
- Arrivals are delivered to the GTK loop as main-context events (no polling
  timeout; the loop sleeps fully between triggers). Rapid sequential requests
  are coalesced so only the newest request of a burst is presented. Future
  asynchronous analysis results must use the same sequence fencing before
  updating this same window.
- Primary-selection support differs between Wayland clients. This milestone
  intentionally does not fall back to stale clipboard data or monitor changes.
- Translation, vocabulary analysis, IPA, pronunciation, storage, and review
  remain future milestones.

## Manual acceptance checklist

1. Start one seltrans process; confirm the GTK window has not popped up.
2. Select acknowledged in app A and press Alt+Q. Verify word label.
3. Select "This is not so much A as B." in app B, press Alt+Q again. Verify
   passage label and **one updated window**; no second GUI init.
4. Hide the window with Esc and trigger another selection; window reappears.
5. Run seltrans again in another terminal; verify duplicate resident is
   rejected without disrupting the first instance.
6. Quit the resident; trigger again and verify a nonzero not-running error.
7. Restart the resident after an unclean process exit; stale socket is cleaned
   without damaging a newer running resident.
8. Confirm primary selection is captured before any popup receives focus.

These interactions require a Fedora/GNOME/Wayland session and cannot be
certified by headless unit tests alone.
